# Contributing to Devungeon

We want the dungeon to be playful, legible and trustworthy.

Useful contributions include game feel, procedural generation, original assets, accessibility, browser rendering, documentation, tests, project adapters and Agent event adapters.

1. Read the [full PRD](docs/PRD.md), [architecture](docs/ARCHITECTURE.md), [acceptance contract](docs/ACCEPTANCE.md) and [Agent rules](AGENTS.md).
2. Open or reference an Issue stating the experience to improve and what observable behavior will change.
3. Avoid storing private user or repository data in tests, examples, screen recordings and screenshots. Use synthetic fixtures.
4. Describe which integrations are real and which are demo. Include reproduction steps, test evidence and known limitations.
5. Verify that all source code and game assets you add have compatible, explicit licenses. Do not use extracted art/audio from commercial games.
6. For new world themes, keep truth/status semantics intact even when changing visuals.

Code of conduct: be respectful and constructive; attack ideas and bugs, not people. Maintainership and governance can be formalized as the community grows.
