# Workspace dependency decision · 2026-11-13

Scope: React workbench plus integration with the committed HERO game, not a replacement engine or provider SDK. Reviewed the repository shortlist, upstream docs and exact npm manifests before installing. Versions are pinned in package manifests and the **root** npm lockfile. No service, key, hook, global installer or telemetry added. The package-local lockfile was replaced by root workspace installation at integration.

The 3D entries reuse HERO's exact Three.js 0.187.0, React Three Fiber 9.8.2 and Rapier 0.21.0 through the root workspace, without a second renderer or physics dependency. Vite deduplicates React/React DOM across package and game imports. Root compiler version 7.0.2 and the package's 5.9.3 are independently pinned and both builds are checked.

Research stops with the runnable integration, audit and measured bundles. Installed transitive license/advisory results are in VALIDATION.md and `docs/HERO_LICENSES.json`; root and workbench builds share regenerated third-party notices. Unmodified MPL-2.0 Lightning CSS is build tooling, not browser runtime code. Runtime notices also retain tslib (0BSD) and inherited HERO packages' licenses. No third-party fonts/images/audio were imported by S4. Original 2D glyphs are code-native rect grids under Apache-2.0, and the reused HERO art keeps its recorded provenance. Roll back the S4 integration commits to remove the primary-App connection; no provider account/settings are modified.

The optional native readiness probe uses the already-installed Codex CLI; no executable is installed or bundled. It only initializes the documented stdio protocol and lists permission profiles, with no thread/turn or inference. Official protocol source: https://learn.chatgpt.com/docs/app-server . Actual account access and model control are not claimed by that probe.

The separate default-off text experiment reuses the same installed CLI and documented JSONL App Server interface, Node HTTP/child_process/filesystem primitives, existing Zod models and the existing React sheet. It adds no package, SDK, installed service, MCP server or hook. The local generated CLI schema (0.167.0-alpha.4.1, ignored output) confirms ephemeral threads, named read-only profiles, `environments: []`, empty capability roots and turn events; official [configuration examples](https://learn.chatgpt.com/docs/config-file/config-sample) document disabling MCP, shell/apps/hooks and web search. Effective overrides are checked before any turn. Fixture tests do not establish actual configured CLI compatibility or model execution; those remain pending owner-scoped account use. Output/audit data stays ignored and browser code never imports the server implementation.

## Wave 2 localization decision · 2026-11-14

Considered maintained i18next/react-i18next (https://www.i18next.com/overview/typescript) and the repository-approved small typed catalogue. For two offline built-in locales, reuse existing React Context and native Intl (https://tc39.es/ecma402/) without another dependency or lockfile. Finite keys, resource/placeholder/plural parity, Chinese fallback, escaped text interpolation and local storage failure tests keep this bounded. HERO owns game-catalogue.ts; shared resources assemble it into the same provider. This is not a general translation engine or cloud service. Original source/authorization text stays intact. New languages or remote resource loading should trigger a fresh library evaluation.
