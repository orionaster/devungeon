# S1 dependency decision · 2026-11-13

The actual problem is desktop-browser pixel combat sharing a scene with a React workbench. The existing broad comparison in TOOLS_AND_SKILLS.md was reviewed before installing.

Selected React 19.3.1 / React DOM 19.3.1, R3F 9.8.2 (peers React >=19 <19.4, Three >=0.156), Three 0.187.0; MIT. Direct `@dimforge/rapier3d-compat` 0.21.0, Apache-2.0, supplies swept kinematic character collision in a renderer-independent engine. The maintained React Rapier 2.2.0 supports R3F9/React19 but pins Rapier0.19.2; direct Rapier avoids React ownership of game simulation and permits headless lock/combat tests. No duplicate physics engine. Drei is deferred: quarter-turn cameras need no additional helper dependency. Phaser/Pixi would need a second 3D stack; Godot web export complicates the native workbench. No paid services, global installs, hooks or keys.

Vite8.3.8 MIT requires Node20.19+ or22.12+; tested host Node24.13.1. TypeScript7.0.2 Apache-2.0, tsx4.23.15 MIT; CLI-only Playwright0.1.24 Apache-2.0 for browser verification. Exact versions and resolved transitive integrity are in package-lock.json. Install with npm ci; no postinstall downloads of game art.

Primary sources reviewed: https://r3f.docs.pmnd.rs/getting-started/introduction ; https://github.com/pmndrs/react-three-rapier ; https://rapier.rs/docs/user_guides/javascript/character_controller/ ; package release manifests from npm registry. Official Kenney Tiny Dungeon remains a reviewed CC0 candidate but no asset bytes imported: S1 uses original code-authored 16px pixel art, licensed under this repo's Apache2. No fonts/music downloaded.

Before delivery: npm audit, complete resolved-license inventory, build, engine tests and actual browser integration. Evidence/results are recorded separately; package compatibility alone is not a gameplay claim. Rollback is removal of S1 commits; no persistent bridge or account permissions are installed.

Resolved review: `docs/HERO_LICENSES.json` enumerates52 installed third-party package manifests, generated by `node scripts/dependency-licenses.mjs`; distribution notices are included at `apps/web/public/THIRD_PARTY_NOTICES.txt` and copied by Vite into the app. Most are MIT/Apache2; Vite's unmodified Lightning CSS1.33.0 and its Windows build dependency use MPL2.0. These are build tools, not imported game code, and their complete provided notices are retained. [Mozilla's FAQ](https://www.mozilla.org/en-US/MPL/2.0/FAQ/) and [upstream license](https://github.com/parcel-bundler/lightningcss/blob/master/LICENSE) were reviewed for file-level coverage; no project license changes. Platform-optional packages absent on this Windows host remain integrity-pinned by the lockfile. Prettier3.6.2 (MIT) was added solely for readable source formatting. `npm audit` currently reports0 known advisories. This review is package metadata/license text inspection, not a full third-party source security audit.
