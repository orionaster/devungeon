## Semantics and safety

Objects use a bounded registry: map-table/trace-dependencies, access-gate/preview-access, relay-board/route-signal, archive or test-bench/compare-evidence, unknown-plinth/inspect. These are extensible display capabilities, not project classifications. Public Issue/PR existence means an observed work item; functionality and acceptance stay unknown. Original evidence remains visible and unmodified. Game-only rehearsal never executes authentication, deployment or provider work.

WorkActivity has exact source/project/revision/agent/task/feature/object identity, typed operation, source kind, explicit confidence, lifecycle/timestamps and honest mode. Runtime resolver must join it to current context and object-supported operations and fail closed for contradictions, future/expired/replay/disconnected/project-only activity. Terminal lifecycle suppresses older running work; no forever-working animation. A local program is never labeled a real Agent/provider.

## Acceptance and evidence

At least three differentiated areas across two graphs, one actual public fact → generated object → player interaction → original evidence chain, two distinct task-bound DEMO behaviors plus actual bounded read-only observation, deterministic content/layout and localized UI preserving source truth, combat/locks/camera/permissions/disconnect regressions. Record real browser screenshots/video and test report. Independent new-user comprehension and owner acceptance must remain pending until humans perform them; automated playthrough is not that evidence. No final merge to main or public deployment.
