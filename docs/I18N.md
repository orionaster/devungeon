# Devungeon — 中文优先 / 中英文切换规范

FORGE 分支补充（2026-11-14）：首个世界包的统一游戏、项目事实、来源模式与工作台已接入同一 Provider；实际双语浏览器结果见 [集成验证](FORGE_INTEGRATION.md)。下文的原始规范状态保留为需求基线，不代表当前分支仍未实现。

> 确认日期：2026-11-13 | 状态：V1 正式要求，尚未实现 | 追踪 Issue #10

## 一句话原则

**默认让用户以简体中文完整玩游戏、理解项目、管理 Agent；需要时可以一键切换英语，而不改变任何工作事实或游戏状态。**

## 支持语言和切换

- 内置 zh-CN 和 en-US 两种完整界面语言。首次使用默认 zh-CN，不依赖浏览器系统语言。
- 在进入游戏前的主菜单、游戏 HUD 和 Agent 工作台都可以找到明显的“中文 / English”选项，支持键盘操作与屏幕阅读器。
- 用户显式选择语言后，偏好保存于本机。切换应即时生效，不要求页面刷新、不重置角色位置/战斗/聊天/Agent 任务/审批状态。
- 缺失翻译的回退和错误日志必须可审查；禁止把国际化缺口静默渲染为空白。

## 翻译范围

所有由 Devungeon 自身编写的用户界面都必须完整覆盖：欢迎页、游戏目标/操作提示、HUD、角色属性、战斗结算、关卡/房间面板、地图状态、项目状态、Agent 角色/工作状态、任务、活动时间线、聊天占位文字、连接状态、权限审批、确认、错误消息、加载/空状态、工具提示、ARIA 文本。

## 动态内容与来源约束

- **不改变事实原文。** 外部 GitHub Issue/PR/Commit 标题、代码、测试日志、Agent 原始回复、外部文档、ID、证据链接和签署/授权内容应保留原始值与来源。
- 用户可以在中文界面中读取简明中文说明/概述；如果缺少有根据的中文说明，显示“原文（英语）”并提供来源，不要凭空生成完成状态。
- 允许在授权、安全边界内引入本地/已获批准的中文解释能力；没有授权不得把私有代码、日志或 Agent 对话上传给第三方翻译服务。
- 未来 Agent World Designer 可输出多语言叙事文本字段，但项目结构、功能 ID、房间锁、完成状态、证据以及 AI 决策不可由语言切换改写。
- 代码命令、终端输出、变量名、URL 和外部产品品牌保持原文，必要时给出中文解释，绝不自动翻译可执行指令。

## 协议与实现建议

- 在现有 React Web 应用和 workspace-ui 中使用**同一个 locale 状态/Provider 与翻译 key 命名空间**，优先评估成熟的 react-i18next/i18next；如采用简洁 typed dictionary，也必须有可维护的插值、复数/日期格式、回退机制。
- 建议语言包按 game.*, world.*, agent.*, work.*, common.*, errors.* 等语义命名，避免按组件文件路径硬编码。完整 zh-CN/en-US 翻译 key 应保持一致。
- 代码中只使用稳定的状态 enum / 任务 ID / Agent ID / world seed 来计算规则。语言只作用于呈现层；切换语言不得触发地图重新生成或写入 project truth。
- 日期与时间按选中的 locale 格式化，同时保留标准化原始时间字段；状态日志要能找到真实原始事件。
- 中文字体使用能清楚显示简体中文的常规分辨率 UI 叠层与系统字体回退，不把汉字压入 16×16 像素字格。游戏本身仍保持原创新像素地牢风格。
- 新增依赖前遵守现有工具尽调和锁定依赖规范；优先复用，避免每个 Agent 自己造一个本地化系统。

## 模块责任

- **WIZARD（主负责）**：语言 Provider/资源、开关、Agent 工作台与审批、错误/连接状态，端到端双语测试。
- **HERO**：游戏菜单/HUD/教程/战斗结果/房间与角色检查 UI，验证语言变更不重置实时游玩。
- **BUILDER**：WorldBlueprint、ID 与布局始终语言无关；游戏房间/区域的 display 文本可本地化，可保留原文和有根据的中文说明。
- **SCOUT**：保留所有外部原始数据、原始时间和证据链接；为 display 层提供可信标签和原始来源，绝不把翻译写回数据源。

## 验收

1. 首次启动就是简体中文，主要功能无需读英文即可理解。
2. 游戏运行中 中文 → English → 中文 立即切换，角色、敌人、任务、Agent 状态不重置。
3. 关键五个画面两套语言均有实际浏览器截图：主菜单、战斗 HUD、锁门/房间检查、Agent 聊天/工作台、审批/异常。
4. 自动检查语言 key 完整性、缺失项、占位插值；真实浏览器完成键盘操作、中文换行、字体和状态延续测试。
5. 项目真实数据、证据、任务进度、权限及游戏状态前后完全一致；没有未经批准的翻译服务请求和私有数据外传。

## 与游戏世界类型选择的关系（ADR-0002）

**语言切换和世界选择是两个独立维度。** 用户界面的 zh-CN / en-US 只决定菜单、状态、工作台等文案；项目自身的“设计语言”（品牌风格、产品叙事、用户体验）可能是 AI 推荐游戏世界的输入信号，但不能用语言环境、编程语言或国家简单决定世界类型。切换 UI 语言绝不能改变 WorldExperience ID、项目进度、Agent 状态、游戏玩法或已有布局。参见 ADR-0002-PROJECT-ADAPTIVE-WORLDS.md。
